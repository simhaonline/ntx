Architectural Pillars of Nityaksha

Engineered from first principles in pure Rust for deterministic enterprise AI agent execution.

Pure Native Rust Control Plane

Zero Python or Node.js runtime dependencies. Compiles to a single stripped binary under 1MB with sub-millisecond cold boot latency and under 12MB RAM utilization.

Self-Contained Agent Memory Stack

No PostgreSQL, pgvector, or Redis required. Features native Relational ACID WAL, Dense SIMD float vector indexing, Sparse BM25 inverted index, and Content-Addressed Storage (CAS) with MVCC versioning.

Deterministic AI Harness & Loop Breaker

Enforces physical loop step limits and outer runtime budgets (CPU, RAM, time). Detects and forcefully terminates file thrashing and hash oscillation loops.

Kernel-Enforced POSIX Sandboxes

Short-lived Linux namespaces (Mount, UTS, IPC, PID, Net) coupled with Cgroups v2 quotas (`memory.max`, `pids.max`, `cpu.max`) preventing unconfined host mutation.

HITL Merge Gates & RedTeam Shield

Mandatory cryptographic approval tokens intercept destructive actions (production git pushes, database drops, capital allocations). Pre-flight adversarial heuristics block prompt injections.

Hot-Swappable Multi-Provider Adapters

Standardized tool call and inference interfaces. Seamlessly switch between OpenAI, Anthropic, Gemini, DeepSeek, and local Ollama/LMStudio engines without changing execution code.

Frequently Asked Questions

Direct technical answers regarding Nityaksha's architecture and deployment.

Is Nityaksha purely built in Rust?

Yes. The entire control plane, AI harness, vector database, and CLI are 100% written in pure native Rust. There are zero Python runtime dependencies and zero Node.js wrappers.

Are external databases like PostgreSQL or pgvector required?

No. Nityaksha includes its own native Agent Memory Stack with Relational ACID WAL, Dense SIMD float vector cache, BM25 inverted index, and Multimodal CAS stored directly in memory or local disk directories.

How does it prevent agent runaway loops and thrashing?

Nityaksha implements physical loop iteration counters and task runtime budgets (CPU, memory, time). It detects repetitive file mutation oscillation and forcefully terminates stuck loops with deterministic hard exits.

How do I deploy this landing page on Plesk?

Connect your Plesk domain to the GitHub repository https://github.com/simhaonline/ntx.git. Plesk will pull this exact index.html directly into your web root (/httpdocs) and serve it immediately without any build steps.
