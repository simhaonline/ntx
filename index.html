Frequently Asked Questions

Direct technical answers regarding Nityaksha's architecture and deployment.

Is Nityaksha purely built in Rust?

Yes. The entire control plane, AI harness, vector database, and CLI are 100% written in pure native Rust. There are zero Python runtime dependencies and zero Node.js wrappers.

Does Nityaksha require PostgreSQL or pgvector?

No. Nityaksha includes a self-contained Agent Memory Stack featuring an ACID write-ahead log (WAL) relational store, dense SIMD float vector indexing, and sparse BM25 retrieval without external daemons.

How do Human-in-the-Loop (HITL) gates function?

When an agent initiates a high-risk action (such as production code pushing, deleting files, or capital allocation), execution is forcefully suspended at the harness layer. Downstream steps are blocked until a matching cryptographic approval token is submitted.

Can Nityaksha run in air-gapped sovereign environments?

Yes. Nityaksha is completely local-first and self-contained. It executes inside air-gapped environments, private VPCs, and edge servers with local LLM runtimes (Ollama, LMStudio, llama.cpp), guaranteeing zero external telemetry or third-party cloud leakage.
